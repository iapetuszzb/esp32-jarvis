摄像头曾在重启后短暂传图，随后持续断流。此版改为热点内加密 TCP 优先 → Android HTTPS 中转，保留 UDP 兼容回退及可选 HTTPS 直传，并主动释放过期画面。此为原型预发布，需同时升级 APK 与 ESP32 固件。

- ESP32 自动连接热点网关 TCP 19422；逐帧等待手机认证重组确认，800 ms 超时关闭连接、归还摄像头缓冲，下一轮取新图，不积压或重发旧图。TCP 不可用时回退 UDP 19421，分片保持 AES-256-GCM 加密。
- Android 新增独立摄像头中转前台服务，不需要开启语音或麦克风。只重组最新一帧，缺片超过 1 秒释放；待发帧超过 2 秒释放；最多一个 HTTP 上传和一个最新待发帧。
- 服务器每 250 ms 扫描，超过 4 秒关闭并释放 PIL 像素；替换时立即关闭旧图，模型推理副本用完关闭。状态查询不再复制图像，元数据最多 32 个会话。
- 手机携带捕获时间上传，服务器拒绝过期画面，迟到的旧捕获不覆盖新图。
- Windows 烧录脚本新增 `-ApplicationOnly`，适用于已经使用本项目相同分区的设备，保留 NVS 配网配置。

验证：ESP32 编译通过；Android 正式构建、11 项 JVM 测试、Lint 通过（0 errors / 10 warnings）；服务端本地和云端 12 项测试通过。已通过 ADB 在用户 OPPO（PME110）覆盖安装正式签名 APK，实际开发板应用区写入并通过哈希校验。手机合成图中转测试 15 / 15 帧得到确认，云端收到其中 10 张新图。随后真实 ESP32 → OPPO 热点 → 云端链路恢复上传，用户确认可用；完整计数及观察时间见 `docs/VALIDATION.md`。初期仍观察到发送超时重连和超过 4 秒的短暂过期，尚未完成数小时、锁屏与热点切换验收。

升级后开启 2.4 GHz 手机热点，在 App 点击“开启摄像头中转”。旧设备使用相同分区时推荐 `flash_windows.ps1 -Port COM11 -ApplicationOnly`；USB 串口以实际为准。首次烧录使用完整镜像并重新配网。参考仓库 `docs/UDP_RELAY.md`。
