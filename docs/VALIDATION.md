## 真正的公网模型链路

电脑从公网 HTTPS 上传合成的红色正方形、蓝色圆形和绿色三角形。服务运行在 L40S 48 GB，MiniCPM-o 4.5 BF16 / SDPA。中文问题由独立的 Windows Huihui TTS 生成，16 kHz 单声道，长度约 9.33 秒。实时流按每秒一块发送；第 60 秒再次发送相同问题，总计 110 块。

| 指标 | 本次结果 |
|---|---|
| 文字看图接口 | 回答“最左边是红色的正方形。”，含有效 WAV，约 3.92 秒 |
| 实时链路 | 110 / 110 音频块收到推理结果，110 / 110 块使用未过期画面 |
| 实时回答 | “最左边是红色的正方形。最左边是一个红色的正方形。画面中还有一个蓝色圆形和一个绿色三角形。” |
| 单块服务处理时间 | 平均约 456 ms，P95 约 1356 ms；包含服务端排队，不包含完整网络/录音/播放 |
| 首个回传音频 | 从开始发送音频计约 10.48 秒；其中输入问题本身长约 9.33 秒，不是 10.48 秒纯推理耗时 |
| 回传音频总长 | 约 11.64 秒，PCM16 / 24 kHz |
| 会话结束 | GPU 租约释放、busy=false，未报告协议错误 |
| 进程显存 | 测试结束 nvidia-smi 约 26467 MiB / 49140 MiB，含 CUDA 缓存；不是所有场景的显存上限 |

模型在静音一段时间后补充描述了蓝色圆形和绿色三角形，即使 proactive=false 也不能保证绝不主动开口。行为参数是提示约束，不是确定性的事件/对话策略。

本次启用了 8000 / 6000 token basic sliding window，但 110 秒测试不足以证明数小时稳定性；没有独立验证所有上下文裁剪边界。更早的官方素材 30 块测试为单机顺序回放，不与本次公网数据混用。

## 2026-10-16 后续实物联调与 Android v0.1.1

- 实际通过 USB 串口完成 ESP32-S3 烧录，写入哈希校验通过。芯片 rev 0.2，物理 Flash 16 MB，内嵌 OPI PSRAM 8 MB；当前固件使用 8 MB 分区布局。原始 Flash 已保存在本地私有目录，不随发布上传。
- 实际摄像头曾向服务器上传 5 帧，随后串口出现 `start_ssl_client: -80`（`MBEDTLS_ERR_NET_CONN_RESET`）和上传 `status=-1`。这证明摄像头链路曾经连通，不能证明持续上传稳定。
- 用户反馈手机使用移动数据并开启热点，手机浏览器访问当前服务器 `/health` 得到 `ready:true`、`busy:false`。截图中 App 显示蓝牙设备 Enco R4，但有网络 timeout；未据此认定耳机录音和播报已通过。
- Android v0.1.1 将状态查询与文字请求分开调度，限制状态查询同时最多一次并设置 12 秒总超时，增加独立网络检查和明确错误提示；DNS 优先 IPv4，同时保留 IPv6 回退。尚未确认实际手机超时是否由 IPv6 引起。
- `assembleRelease`、`testReleaseUnitTest`、`lintRelease` 通过：4 项 JVM 测试零失败，Lint 为 0 errors / 8 warnings。新增测试验证慢状态请求不阻塞文字请求、重复轮询被跳过、取消后可重新查询，以及 IPv4 优先但保留 IPv6。
- v0.1.1 使用原发布密钥签名；APK 签名及版本信息在发布前校验。没有已授权的 ADB 手机，因此 OPPO 上安装升级后的联网、实际语音和持续画面仍需现场确认。此次未改动或重刷固件，也未重复运行 v0.1.0 的 GPU 合成媒体测试。
